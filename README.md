# MiniVim

> 一个面向大一学生的 C++17 课程项目: 从零实现一个可以在终端中运行的, 具有基本 Vim 操作方式的文本编辑器.

- 对于该项目中出现的快捷键简记方式的介绍, 可以在 Vim 中执行 `:help key-notation` 或访问
  [官方文档](https://vimdoc.sourceforge.net/htmldoc/intro.html#key-notation) 来查看.
- 在 vscode 中, 你可以用 `<C-S-v>` 来启动 vscode 内置的 Markdown 阅读模式, 读起来更轻松.
- 如果你想学习如何使用 Vim, 请阅读 [Vim 入门笔记](./IntroForVim.md).

---

## 学习目标

完成项目后, 你应该能够:

- 熟悉 C++ 的基本 **语法** 与 STL, 如 std::filesystem, std::optional, std::vector;
- 掌握基本的 **模块化设计** 思想, 将一个复杂问题拆分成若干职责明确, 相互协作的模块;
- 理解 **封装** 的意义, 通过类的公开接口隐藏内部状态和实现细节;
- 熟悉 C++ 的基本面向对象程序设计方法;
- 建立基本的 **单元测试** 意识: 将容易独立验证的逻辑从交互式程序中分离出来, 并通过测试检查模块行为和边界情况;
- 对 Vim 之类的文本编辑器的底层设计实现有新的了解.

## 框架

对 MiniVim 的 Basic 部分, 我们准备了一个框架来方便完成:

```text
MiniVim
├── Makefile
├── src
│   ├── *.hpp
│   └── *.cpp
└── test
    └── *.cpp
```

完成 MiniVim 不一定需要使用我们提供的框架, 如果你愿意 everything starts from scratch 也是可以正常完成 MiniVim
并通过评测的; 为了简化 Basic 部分的实现流程, 我们建议使用该框架.

### 框架结构

我们在 `src/` 内的文件内留了很多注释, 它们有些是讲解设计逻辑的, 有些是讲解接口要求的. **请不要忽视这些注释**.

你需要完成的核心模块包括:

| 模块               | 作用                               |
| ------------------ | ---------------------------------- |
| `TextLayout`       | 缓冲区列与屏幕列之间的转换         |
| `Buffer`           | 文件内容, 文本修改, 修改标记与保存 |
| `Window`           | 光标, 期望列与视口                 |
| `NormalModeParser` | Normal 模式命令解析                |
| `Renderer`         | 从状态生成一帧 ANSI 文本           |
| `Editor`           | 事件循环, 模式切换与动作执行       |
| `main`             | 参数处理, 对象创建与顶层错误处理   |

请注意, 如果你修改了已有的 public 接口, 可能会导致 test 模块无法正常工作. 框架中提供的 test 是通过这些接口进行测试的.

### 环境安装

```sh
# 安装基本编译工具
sudo apt install build-essential
# 检查
g++ --version
make --version
```

### 运行

```sh
# 编译 MiniVim 到 code
make
# 运行 MiniVim
./code [parameters...]
```

为了能够在 ACMOJ 上进行评测, 需要把可执行文件放到 `code` 处; 如果你想修改 `make` 得到的可执行文件名 (如 `mvim`),
你需要修改 `Makefile` 中 `TARGET` 的值:

```Makefile
TARGET := code
```

### 测试

```sh
# 编译并运行测试模块
make test
```

### 清理编译中间文件

```sh
make clean
```

### Hint: 一次按键如何流过系统

![MiniVim 按键处理流程](./docs/images/key-processing-flow.png)

`Editor::processKey ()` 是模式分发的唯一入口. 只有 Normal 模式会先经过 `NormalCommandParser` 并产生 `EditorAction`;
Insert 和 Command-line 模式分别由 `Editor` 中对应的 handler 直接处理. 三条路径都在 `Editor` 中完成本次按键的语义;
如果程序继续运行, `Renderer` 再根据 `Buffer`, `Window` 和 `RenderState` 生成下一帧, 最后交给 `Terminal` 输出.

## 项目要求

### Basic

你必须实现 Basic 部分才能获得基础分数并继续完成 Advanced 部分与 Extra 部分. Basic 部分的最终得分即为 ACMOJ
上评测得到的分数.

#### Basic 概述

MiniVim 的哲学是模态编辑, 高效的编辑操作依托各模式间的切换完成. 简而言之, 在 Basic 部分中, 你需要为 MiniVim 实现最基础的
3 种模式:

- **Normal**: 移动光标, 执行编辑动作或进入其他模式;
- **Insert**: 插入和删除文本;
- **Command-line**: 输入保存, 退出等以 `:` 开始的命令;

并为每个模式实现一些最基础的功能.

- 在 Basic 部分, 你可以简单地认为屏幕由两部分构成: 屏幕最下面一行的保留部分 (用于输入命令, 显示信息等),
  以及上面其余的编辑部分, 即缓冲区.
- Normal 模式与 Insert 模式主要操作缓冲区, 而 Command-line 模式则会将保留部分当成一块用于输入命令的命令缓冲区来操作.
- 在 Basic 部分中, 所有要求的功能在终端上打印的字符都以默认颜色与属性呈现 (具体来说, 都使用默认前景色与背景色;
  没有额外终端字符属性, 如粗体). 也就是说, 你不需要操作任何颜色与属性即可通过 Basic 评测.
- `<C-q>` 在该项目中是未被绑定的保留键位. 你可以将其实现为紧急退出键, 按下后在任意模式下结束程序, 以便方便调试 Basic
  及之后的部分. 我们不会对该键行为进行评测.

#### Normal 模式 (Basic)

在 Normal 模式中, 光标总会停留在某一个字符上 (对于空行, 则只能停留在不存在字符的位置) .

在 Basic 部分, 你需要为 Normal 模式实现以下的功能键.

##### `h` (Basic)

- 光标向左移动一个字符; 如果光标在行首则不变.

##### `l` (Basic)

- 光标向右移动一个字符; 如果光标在行末则不变.

##### `j` (Basic)

- 光标向下移动一个字符; 如果光标在最后一行则不变. 若光标移动到的位置在这一行行末之后, 则向左移动到行末位置.

##### `k` (basic)

- 光标向上移动一个字符; 如果光标在第一行则不变. 若光标移动到的位置在这一行行末之后, 则向左移动到行末位置.

##### `i` (Basic)

- 在光标所选字符之前进入 Insert 模式. 若光标处在空行, 则在该空行的唯一位置进入 Insert 模式.

##### `a` (Basic)

- 在光标所选字符之后进入 Insert 模式. 若光标处在空行, 则在该空行的唯一位置进入 Insert 模式.

##### `:` (Basic)

- 进入 Command-line 模式.

---

- 请注意对于空行, 该行的行末位置不存在实际字符; 而对于非空行, 该行的行末位置是最后一个字符的位置.

- 对于以上的移动的 curswant 功能, 不要求在 Basic 部分中准确实现, 但是在 Advanced 部分中会进行评测.
  具体关于该功能的说明详见 [curswant](#curswant).

#### Insert 模式 (Basic)

在 Insert 模式中, 光标总会停留在某一个字符上, 或是停留在行末位置, 即行末字符之后的位置上 (你可以假想为那里存在一个换行符
`\n`; 事实上, Vim 就是这么实现的).

在 Basic 部分, 你需要为 Insert 模式实现以下的功能键:

##### `{printable ascii}` (Basic, Insert)

- 在光标所选字符之前插入输入的字符, 并将光标自然移动到下一个位置上.
- 这部分功能键限定为所有 ASCII 码在 `0x20~0x7e` 之间的字符.

##### `<BS>` (Basic, Insert)

- 删除光标所选字符之前的字符, 并将光标自然移动到前一个位置上.
- 若光标处在行首 (或空行), 则拼接该行与上一行, 并将光标自然移动到上一行原行末位置上.
- 若光标处在文件首, 则无效果.

##### `<CR>` (Basic, Insert)

- 在光标所选字符之前位置切分该行, 换行至下一行, 并将光标自然移动到下一行的行首.

##### `<Esc>` (Basic, Insert)

- 进入 Normal 模式, 并将光标自然移动到前一个位置上. 若光标处在行首则不移动光标.

---

#### Command-line 模式 (Basic)

在 Command-line 模式中,

- 光标总会停留在窗口底部的命令输入部分, 总体操作逻辑类似于 Insert 模式中的一行, 并且此时行首必定以 `:` 开头.
- 相较于 Normal 模式的状态, 除了屏幕最下面一行, 其余部分显示内容应保持不变.
- 进入到 Command-line 模式时, 初始输入的指令, 即命令缓冲区部分为空.
- 在 Basic 部分中, 你只需要考虑光标处在行末位置的情形. 也就是说, 任何停留在 Command-line
  模式的操作最终都会将光标移动到行末位置.

在 Basic 部分, 你需要为 Command-line 模式实现以下的功能键:

##### `{printable ascii}` (Basic, Command-line)

- 在光标所选字符之前 (在 Basic 部分中, 即行末) 插入输入的字符, 并将光标自然移动到下一个位置上 (在 Basic 部分中, 即行末).
- 这部分功能键限定为所有 ASCII 码在 `0x20~0x7e` 之间的字符.

##### `<CR>` (Basic, Command-line)

- 执行当前命令缓冲区中的指令, 待执行完毕后进入 Normal 模式.

##### `<Esc>` (Basic, Command-line)

- 进入 Normal 模式, 并将光标移动到进入 Command-line 模式前原来的位置. 舍弃在 Command-line 模式中的所有输入.

---

在 Basic 部分, 你需要实现以下命令:

##### `:wq [file]` (Basic, Command-line)

- 将缓冲区内容写入到该路径所在文件.
- 若文件不存在, 则创建新文件并写入.
- 若文件已存在, 则覆盖原有内容.
- 在 Basic 部分中不需要考虑文件权限等问题.

##### `:q!`, `:quit!` (Basic, Command-line)

- 舍弃缓冲区内容并退出 MiniVim.

---

- 若当前输入的指令为空字符串, 则不会有任何行为.
- 若当前输入的指令非法, 在 Basic 部分中你可以直接忽略执行它. 在 Basic 部分中, 我们不会对未提及的命令评测.

### Advanced

Advanced 部分包含若干可选功能. 他们之间大部分相互独立, 但有些功能存在依赖关系, 这意味着部分功能的实现需要其他功能来支持.
例如, 一般来说, 你需要实现 `e` 才能实现 `ce`.

对于 Advanced 部分, 你可以选择任意一部分功能来实现.

- 每个功能在 ACMOJ 中都有独立测试点计分, ACMOJ 给出的总得分在折算之后作为 Advanced 部分的实际得分. 折算公式为 $ y = f(x)
  $, 其中 $x$ 为你的 ACMOJ 计分, $y$ 为你的实际得分.
- 如果你使用我们提供的框架, 从本部分开始, 除 Basic 中已经给出的公共接口与 `Terminal` 外, 不再限制 `src/`
  中其他模块的接口设计.
- 你可以添加新的类, 数据结构, public / private 接口或源文件, 但已经完成的 Basic 行为不得被破坏.
- 除非特别说明, 本节中的命令语义按照 Vim 的行为定义. ACMOJ 的评测不会测试未提及的 Vim 行为与特性. 若下文明确给出与 Vim
  默认行为不同的要求, 则以该要求为准.
- 有些功能的实现与大量操作相关联 (如 `[count]{operation}`, 许多操作都支持加上计数),
  则该功能的评分会在所有所关联的操作下独立评分.

#### 独立评分功能概述

##### `[count]{operation}`

大多数 Normal 与 Visual 模式命令可以在命令前连接一个无前导零十进制 `[count]`. 这模糊地表示该命令的重复次数,
但是对于部分命令, 其实际含义存在特殊情况或并不表示重复次数, 这会在具体命令中详细说明.

- 连续数字共同构成一个 `[count]`. 若命令没有显式 `[count]`, 则认为 `count` 为 1.
- 命令操作中的头部 `0` 不属于 `[count]`, 而作为 `motion` 处理; 已经开始输入 `[count]` 后, `0` 则属于 `[count]`, 因此
  `[count]` 一定不包含前导零.
- `count` 可能会很大. 对于可能造成溢出的 `count` 值, 你可以设置一个最大 `count` 值进行截断. 对于部分指令,
  你需要进行优化来保证正确高效处理足够大的 `count`.

##### `{operator}{motion}`

在一个范围操作命令 `{operator}` 后指定一个移动命令 `{motion}`, 表示以 `motion` 指示的移动位置为终点进行该操作.
对于不同操作, 该组合命令的含义是不同的.

大部分行内移动或小范围移动的区域从当前字符到移动到的字符; 部分跨行移动的区域从当前行到移动到的位置所在行, 以行为单位
(Linewise). 具体含义见各操作小节.

- 可以结合计数: `[count]{operator}[count]{motion}`. 若两个 `[count]` 都被显式指定, 则最终计数值为它们的乘积.

##### `<Esc>`

在 Normal 模式下, `<Esc>` 会打断当前未完整键入的任何命令, 并清空当前键入命令; 若当前未残留不完整命令, 则无效果.

- `<Esc>` 会打断并清空包括 `[count]`, `{operator}` 等所有命令组成部分.
- 对于所有多键的操作, 你**需要同时完成 `<Esc>` 打断的正确行为才能够通过评测**.

##### curswant

`curswant` 是光标的一个列坐标变量, 用于记录光标在垂直移动 (如按 `j` / `k`) 时的理想列位置.
它确保了上下移动时光标能尽可能停留在同一视觉列.

例如, 在第 1 行的第 20 列按 `j` 下移; 第 2 行只有 10 个字符, 光标实际停在第 10 列, 但 `curswant` 仍是 `20`. 再按 `j`
下移时, 若第 3 行够长, 光标会跳回第 20 列, 而不是留在第 10 列.

- 在 Vim 中, 通过 `:echo getcurpos()` 可以查看光标位置信息, 返回格式为: `[bufnum, lnum, col, off, curswant]`.
- 当你使用 `$` 等操作将光标移到行尾时, `curswant` 会被设为一个极大的值, 表示 "想去最右边". 只要不进行水平移动或编辑,
  之后无论上下移动到多长的行, 光标都会直接停在行尾.
- 垂直移动不会改变 `curswant` 的值.

#### Normal 模式

下面是 Normal 模式下各功能的实现要求; 其中模式切换一节同时给出进入 Insert / Replace 模式后的输入行为.

##### 动作 (`47pts`)

###### `h`, `l`, `j`, `k` (`6pts`)

这一节四个键的方向和 Basic 相同; 现在需要支持 `count`, 并正确维护 `curswant`.

- `[count]h`: 光标向左移动 `count` 个字符. (`1pt`)
  - 不跨行: 可移动距离不足 `count` 时停在行首.
- `[count]l`: 光标向右移动 `count` 个字符. (`1pt`)
  - 不跨行: 可移动距离不足 `count` 时停在行末.
- `[count]j`: 光标向下移动 `count` 行. (`2pts`)
  - 按文本行移动; 剩余行数不足 `count` 时停在文件最后一行; 已在最后一行时不再移动.
  - 目标列由 `curswant` 决定: 尽量停在原显示列; 行太短时停在行末; 空行停在该行唯一位置.
  - 本次未到达期望列时, 后续移动到足够长的行仍要回到该期望列.
- `[count]k`: 光标向上移动 `count` 行; 除边界为文件第一行外, 规则与 `[count]j` 相同. (`2pts`)
  - 剩余行数不足 `count` 时停在文件第一行; 已在第一行时不再移动.
- 空行上没有字符可移, 因此 `h` 和 `l` 都不移动光标.
- 一个 Tab 只算一个字符; Tab 的显示列规则见选项一节的 `tabstop`.

###### `0`, `^`, `$` (`6pts`)

这一节三个命令用于快速到达一行的开头或结尾.

- `0`: 移动到当前行的第一个字符, 包括行首的空格或 Tab. (`1pt`)
  - `0` 不接受 `count`; 已开始输入 `count` 时, 后续的 `0` 属于 `count`.
  - 完成后把 `curswant` 更新为到达位置的显示列.
- `^`: 移动到当前行的第一个非空白字符. (`2pts`)
  - 当前行全部为空白字符时, 停在该行最后一个字符上.
  - `^` 忽略 `count`.
  - 完成后把 `curswant` 更新为到达位置的显示列.
- `$`: 移动到当前行的最后一个字符, 包括行尾的空格或 Tab. (`2pts`)
  - 把 `curswant` 设为前文所说的极大值 ("始终到行末").
- `[count]$`: 先向下移动 `count` - 1 行, 再移动到该行行末. (`1pt`)
  - 不是重复执行 `count` 次 `$`.
  - 下方行数不足 `count` 时, 到最后一行的行末. 此时仍把 `curswant` 设为极大值.
  - 但如果执行前已经在文件最后一行, 且 `count` 大于 1, 命令失败, 光标不动; `curswant` 仍设为极大值.
    与 `operator` 组合时, 这次失败不修改文本或 register, `c` 也不进入 Insert. 例如单行 `abc` 的行首执行
    `2$`, `d2$`, `y2$` 均不移动光标; 后两者也不删除或复制文本. 从倒数第二行执行 `d99$` 则仍可截断到 EOF.

---

- 当前行为空行时, `0`, `^` 和不带 `count` 的 `$` 停在该行唯一的位置. `[count]$` 仍按上面的规则跨行;
  目标行为空行时, 停在目标行唯一的位置.
- 这里的空白字符指空格和 Tab.

###### `gg`, `G` (`2pts`)

这一节两个命令直接跳到指定行; 行号从 1 开始, 带 `count` 时表示行号而不是移动次数.

- `gg`: 跳到文件第一行. (`1pt`)
  - `[count]gg`: 跳到文件第 `count` 行.
- `G`: 跳到文件最后一行. (`1pt`)
  - `[count]G`: 跳到文件第 `count` 行.
  - `G` 与 `1G` 不同: 无 `count` 的 `G` 到文件最后一行, `1G` 到第一行.
- 指定行号超过文件总行数时都到文件最后一行.
- 到达目标行后:
  - 光标停在第一个非空白字符上.
  - 行内全为空格或 Tab 时停在最后一个字符上; 空行停在该行唯一的位置.
  - 即使目标行就是当前行, 也按上述规则重新定位.
  - 完成后把 `curswant` 更新为光标所在的显示列.

###### `w`, `b`, `e`, `ge` (`9pts`)

这一节四个命令按 word 移动. word 由连续的英文字母, 数字和下划线, 或连续的其他非空白字符组成; 空格, Tab 和换行将它们分开,
一个 word 不会跨越两行.

- **空行算一个 word**, 它的开头和结尾都是该行唯一的位置; **只含空格或 Tab 的行没有 word**, 移动时会跳过这些空白.

- `w`: 向后到下一个 word 的开头. (`2pts`)
  - 当前在一个 word 上时, 先越过这个 word; 当前在空白上时, 跳过这些空白.
  - 即使已经在 word 的开头, 也要去下一个, 不能停在原地.
- `b`: 向前到 word 的开头. (`2pts`)
  - 当前在一个 word 内部但不在开头时, 回到这个 word 的开头; 已经在开头时, 去上一个 word 的开头.
  - 当前在空白上时, 跳过前面的空白, 去前一个 word 的开头.
- `e`: 向后到 word 的结尾. (`2pts`)
  - 当前在一个 word 上但还没到结尾时, 到这个 word 的最后一个字符; 已经在结尾时, 去下一个 word 的结尾.
  - 当前在空白上时, 跳过后面的空白, 去后一个 word 的结尾.
- `ge`: 向前到上一个 word 的结尾. (`3pts`)
  - 当前在 word 上时, 无论在开头, 中间还是结尾, 都去上一个 word 的最后一个字符; 当前在空白上时, 去前一个 word
    的最后一个字符.
- 这些命令可以跨行. `w`, `b`, `ge` 会把遇到的空行当作一个 word 停下来, 连续空行也要分别计算; **`e` 是例外, 它跳过空行**,
  继续找后面的非空 word. 只包含空白字符的行对四个命令来说都不是 word.
- 都支持 `count`, 行为相当于连续执行相应命令 `count` 次; `count` 写在整个命令前面.
- 向后找不到目标时, `w` 和 `e` 最多移到文件最后一行的最后一个字符; 对应行为空行时停在该行唯一的位置.
- 向前找不到目标时, `b` 和 `ge` 最多移到文件第一行的第一个字符; 对应行为空行时停在该行唯一的位置.
- 已在对应边界时不再移动, `count` 再大也一样.
- 每条命令完成后, 把 `curswant` 更新为终点的显示列.

---

- 本项目只考虑可打印 ASCII 字符和 Tab, 不要求处理中文等字符的 word 划分.

###### `W`, `B`, `E`, `gE` (`5pts`)

这一节四个命令按 WORD 移动. WORD 是一段连续的非空白字符; 不再区分字母, 数字和标点, 只有空格, Tab 和换行能将它们分开.

- `W`: 向后到下一个 WORD 的开头. (`1pt`)
- `B`: 向前到 WORD 的开头. (`1pt`)
  - 已在开头时去上一个 WORD.
- `E`: 向后到 WORD 的结尾. (`1pt`)
  - 已在结尾时去下一个 WORD.
- `gE`: 向前到上一个 WORD 的结尾. (`2pts`)
- 除把 word 换成 WORD 外, 其余规则分别与 `w`, `b`, `e`, `ge` 相同:
  - 当前在空白上的处理方式不变; 空行算一个 WORD; 只含空白的行没有 WORD.
  - `W`, `B`, `gE` 停在空行, `E` 跳过空行.
  - 同样可以跨行, 支持 `count`, 并按上一节的规则处理文件边界和 `curswant`.

###### Find: `f` / `F` / `t` / `T` / `;` / `,` (`6pts`)

这一节六个命令用于在当前行内按字符查找, 以及重复上次查找.

- 语法为 `[count]f{char}` 等; `{char}` 可以是一个可打印 ASCII 字符或 Tab; 查找只在当前行内进行, 不包含光标当前字符,
  不跨行.
- `f{char}`: 向右找第 `count` 个匹配. (`1pt`)
  - 成功后的光标停在匹配字符上.
- `F{char}`: 向左找第 `count` 个匹配. (`1pt`)
  - 成功后的光标停在匹配字符上.
- `t{char}`: 向右找第 `count` 个匹配. (`1pt`)
  - 成功后的光标停在匹配字符左侧一个字符.
- `T{char}`: 向左找第 `count` 个匹配. (`1pt`)
  - 成功后的光标停在匹配字符右侧一个字符.
- 不足 `count` 个匹配时整个 `motion` 失败, 不停在最后一个已找到的匹配上; 空行同样失败.
- `t` / `T` 找到相邻字符时可以成功但不移动; 成功的零位移与失败不同.
- 输入完整合法参数后立即保存查找种类与字符 (即使本次没有找到); 不保存 `count`; `<Esc>` 或非法参数取消命令, 不覆盖旧记录.
- `[count];`: 沿记录的方向, 使用记录的种类和字符再次查找第 `count` 个匹配. (`1pt`)
  - 无记录时失败.
  - `;` 不改变记录, 也不沿用最初查找的 `count`.
  - 重复 `t` / `T` 时, 排除会使本次光标停留原位的相邻匹配后再计数.
  - 例: 在 `a,b,c` 的 `a` 上执行 `t,` 后, `;` 移动到 `b`.
- `[count],`: 与 `[count];` 相同, 但沿记录的相反方向查找: 记录为 `f` / `t` 时按 `F` / `T` 查找, 记录为 `F` / `T` 时按
  `f` / `t` 查找. (`1pt`)
  - 与 `;` 相同, `,` 不改变记录, 也不沿用最初查找的 `count`; 上述相邻匹配排除规则同样适用.
- 字符查找记录与 `/`, `?` 的搜索记录互不影响.

###### Match: `%` (`3pts`)

这一节的两个形态用于跳转到括号的配对位置.

- `%`: 在当前行从光标处开始向右寻找第一个 `(`, `)`, `[`, `]`, `{` 或 `}` (包含当前位置), 再跳到其配对括号. (`2pts`)
  - 候选为左括号时, 向文件末尾查找; 为右括号时, 向文件开头查找.
  - 可以跨行, 用同种括号的嵌套深度确定配对; 其他种类的括号不影响深度.
  - 配对遵循 Vim 默认的引号与反斜杠处理, 不再把所有引号内括号无条件计入深度. 从双引号外的括号开始配对时,
    跳过双引号字符串内的括号; 反斜杠转义也按 Vim 默认规则处理, 不能仅按出现次数配对.
    例如在 `(")"x)` 的第一个 `(` 上执行 `%`, 应到第 6 列的 `)`, 而不是第 3 列的 `)` (列号从 1 开始).
    不要求预处理指令等非括号匹配扩展, 也不要求配置 `cpoptions` 或按语言进行语法分析.
  - 当前行没有候选或候选没有配对时失败, 保持原位置, 不继续尝试下一个候选.
- `[count]%`: 跳到第 `ceil(count * N / 100)` 行, 其中 `N` 是文件行数. (`1pt`)
  - `count` 必须在 1 到 100 之间, 否则失败; 运算不得溢出.
  - 列位置遵循 `G` 的第一个非空白字符规则.
  - 这是百分比跳转, 不是重复括号匹配.

###### Mark: `m{a-z}` / 精确跳转 (`4pts`)

这一节两个命令用于设置与跳转到小写局部标记, 并规定编辑后的标记维护.

- `m{a-z}`: 将当前 Buffer 位置保存为对应小写局部标记; 同名标记被覆盖. (`2pts`)
- `` `a ``: 反引号后输入同一个字母, 跳到该标记的精确行与字符位置. (`2pts`)
  - 这两种命令忽略 `count`.
  - 未设置或已失效的标记使跳转失败; 非法标记名取消命令.
- 标记维护采用以下课程规则:
  - 将 Buffer 视为各行以一个 `\n` 连接的字节序列, 不额外附加文件末尾换行. 标记锚定一个字节位置, 真正空行锚定其第 0
    列对应的位置 (可能是换行或 EOF).
  - 在标记位置之前或恰好该位置插入文本, 标记随原文本向后移动. 插入换行时也按此规则换算新的行列.
  - 删除半开区间 `[start, end)` 时, 区间内的标记失效; 位于 end 及之后的标记向前移动被删除的字节数. EOF
    的空行锚点不会仅因删除到 EOF 而落入这个半开区间.
  - `~` 的原位字符替换保留标记. 缩进只把原行首空白的替换视为删除后插入; `J` 只删除实际去掉的换行和前导空白,
    插入实际添加的分隔空格. 其他保留文本上的标记按前两条平移.
  - 整行删除也删除相邻的行分隔符: 有后续行时删除该行及其后的换行; 删除到文件末尾且有前置行时删除前置分隔符及末尾行块.
    全部删除后保留一个空行. 整行删除范围内的标记统一失效, 包括位于被删除末尾空行的 EOF 锚点.
  - `cc` 等 Linewise Change 按删除所选完整行块, 再插入占位空行处理; 所选行上的标记统一失效. 后续 Insert
    再按插入规则处理.
  - 一次命令内按文本编辑的先后顺序维护标记, 不因最终文本恢复原样而恢复已失效标记.
- 每条 Normal 编辑命令结束后, Insert 模式每次编辑按键完成后, 将存活锚点换算为行列; 若落到非空行的行末之后,
  限制到该行最后一个字符, 并以此作为后续锚点; 在空行则仍为第 0 列.
- 标记不写入磁盘; 保存文件不清除标记. 标记维护的组合测试只使用本项声明支持的编辑功能; 基础测试用 Basic Insert, 与操作 /
  范围操作 / 寄存器各节的组合需同时实现对应项.

---

- 不要求大写跨文件标记, 单引号跳转, 特殊标记或 jumplist.
- 标记维护不要求复现 Vim 全部 mark 调整机制.

###### Search: `/` / `?` / `n` / `N` (`6pts`)

这一节四个命令用于字面串搜索与重复搜索.

- `/`: 打开向前搜索输入框. (`2pts`)
- `?`: 打开向后搜索输入框. (`2pts`)
- `/` 与 `?` 的输入框规则:
  - 命令提示符本身不属于搜索串.
  - 只要求区分大小写的字面串匹配, 不解释正则表达式, 转义, offset 或 option.
  - 匹配不能跨行; Tab 按一个实际 Tab 字节匹配.
  - `/`, `?` 和反斜杠在输入框内均作为普通搜索字符, 只有 `<CR>` 提交.
  - 支持可打印 ASCII, Tab 和 `<BS>`; `<BS>` 删除末尾一个字节, 不删除提示符; 其他控制键忽略, `<Esc>` 除外.
  - 输入期间不进行增量搜索, 正文与原光标位置不变.
  - `<Esc>` 取消并回到进入前的位置, 不修改搜索记录.
  - 提交非空串后立即保存搜索串与 `/` 或 `?` 指定的方向, 即使本次找不到; 提交空串时复用旧串, 并使用这次输入的方向;
    没有旧串则失败.
- `n`: 按保存的方向重复搜索. (`1pt`)
- `N`: 按相反方向重复搜索. (`1pt`)
  - 尚无搜索记录时 `n` / `N` 都失败且不移动; `n` / `N` 不改变保存的方向; 连续两个 `N` 仍然朝同一个反方向搜索.
- 匹配规则:
  - 搜索按匹配的起始位置排序, 允许重叠匹配.
  - 向前从当前字符之后开始, 向后从当前字符之前开始; 到文件边界后环绕.
  - 每寻找下一个匹配最多完整绕行一周, 原位置的匹配排在一周的最后; 因此只有当前位置一个匹配时可以成功回到原位置.
  - 整个文件无匹配时失败且不移动.
  - `[count]/...<CR>`, `[count]?...<CR>`, `[count]n` 与 `[count]N` 都选择该方向上第 `count` 个匹配, 可以多次环绕;
    不应为超大 `count` 实际循环数十亿次.
  - 成功时光标位于匹配的第一个字符; 失败时光标与 viewport 保持不变.

---

- 不要求高亮匹配或搜索历史列表.

##### 滚动 (`7pts`)

###### Window: `zt` / `zz` / `zb` (`3pts`)

这一节三个命令在不改变文本与光标位置的前提下, 调整 viewport 顶部行 `top`.

本项目不自动折行, 一条 Buffer 文本行占一条屏幕正文行. 设正文高度为 `H >= 1`, 文件行数为 `N >= 1`, 当前行号为 `r` (从 1
开始), viewport 顶行号为 `top`.

- `zt`: 当前行对齐正文顶部; 新的 `top` 为 `r`. (`1pt`)
- `zz`: 当前行对齐正文中间; 新的 `top` 为 `max(1, r - floor((H - 1) / 2))`. (`1pt`)
  - 偶数高度时使用靠上的中间行. 例如正文高度为 24, 当前文件行为 30 时, 新的 `top` 为 19,
    光标位于正文第 12 行; 正文高度为 23 时同样得到 `top = 19`.
- `zb`: 当前行对齐正文底部; 新的 `top` 为 `max(1, r - H + 1)`. (`1pt`)
- 文件开头不足以提供上方文本时, 按上式把 `top` 限制到 1; 文件末尾允许出现 `~` 填充行, 不为填满窗口而把 `top` 往回移动.
- 无 `count` 时光标与 `curswant` 不变.
- 有显式 `count` 时先前往第 `min(count, N)` 行, 按原 `curswant` 选择目标字符, 再对齐; `curswant` 保持不变.
- 这三个命令不修改文本, register 或搜索记录, 不能用于 `operator`.

---

- 仅要求 `zt` / `zz` / `zb`, 不要求 `z<CR>` 等其他 `z` 命令.

###### Scroll: `<C-e>` / `<C-y>` / `<C-d>` / `<C-u>` (`4pts`)

这一节四个按键用于按行或半屏滚动 viewport.

沿用 Window 的 `H`, `N`, `top`, 正文不自动折行. `top` 范围固定为 `[1, N]`, 允许末尾出现填充行.

- `[count]<C-e>`: 将 `top` 增加 `count`, 限制到 `N`; 文本在屏幕上向上移动. (`1pt`)
- `[count]<C-y>`: 将 `top` 减少 `count`, 限制到 1; 文本在屏幕上向下移动. (`1pt`)
- 上述两项优先保持光标 Buffer 位置; 若光标被挤出新的可见文本行区间 `[top, min(N, top + H - 1)]`, 则移到该区间最近的一行,
  按原 `curswant` 选择字符.
- `[count]<C-d>`: 向下半屏滚动. (`1pt`)
- `[count]<C-u>`: 向上半屏滚动. (`1pt`)
- 半屏滚动的步长: 无显式 `count` 时为 `max(1, floor(H / 2))`; 显式 `count` 直接作为本次步长, 不修改后续命令的默认步长,
  也不表示 `count` 个半屏.
- 半屏滚动先将光标行按方向移动步长并限制到文件边界, 再将 `top` 按光标实际移动的行数同向移动并限制到 `[1, N]`;
  最后若光标仍不可见, 只将 `top` 调整到刚好能看见光标的位置. 列按原 `curswant` 选择.
- 四个命令都保留 `curswant`; 目标行过短时停在行末, 空行停在唯一合法位置. 不修改 Buffer, register, 查找记录或 Repeat
  记录, 不能用于 `operator`.

---

- 本节规则为课程固定规则, 不依赖 Vim 的 scroll / scrolloff / startofline 设置.

###### 视口

这一节要求: 光标超出可见范围时, 视口应以使光标重新可见的最小距离上下或左右滚动; 光标仍可见时保持视口不变.

##### 模式切换

`:` 与 `v` 分别进入 Command-line 模式与 Visual 模式, 见对应小节. Insert 模式中 `<BS>` 与 `<Esc>` 的行为沿用 Basic 的
要求; 退出 Visual 与 Replace 模式的 `<Esc>` 见对应小节.

###### Insert Entry (`7pts`)

这一节四个命令用于进入 Insert 模式, 并决定进入时的光标位置.

- `I`: 在当前行第一个非空白字符处进入 Insert 模式. (`2pts`)
  - 当前行存在非空白字符时, 在第一个非空白字符之前进入 Insert 模式.
  - 当前行只包含空格或 `\t` 时, 在第 0 列开始插入; 这是本项目固定采用的规则, Vim 在这里的行为可能随设置不同,
    不作为覆盖本规则的依据.
  - 当前行为真正的空行时, 在该行唯一合法位置进入 Insert 模式.
- `A`: 在当前行行末进入 Insert 模式. (`1pt`)
  - 无论当前 cursor 位于该行何处, 都移动到当前行行末位置并进入 Insert 模式.
  - 当前行为真正的空行时, 在该行唯一合法位置进入 Insert 模式.
- `o`: 在当前行下方插入一个空行, 并在新行进入 Insert 模式. (`2pts`)
  - 始终在当前行下方创建一个新的空行, cursor 移动到新行唯一合法位置并进入 Insert 模式.
  - 当前行为文件最后一行时仍然可以使用 `o`, 此时新行成为文件新的最后一行.
- `O`: 在当前行上方插入一个空行, 并在新行进入 Insert 模式. (`2pts`)
  - 始终在当前行上方创建一个新的空行, cursor 移动到新行唯一合法位置并进入 Insert 模式.
  - 当前行为文件第一行时仍然可以使用 `O`, 此时新行成为文件新的第一行.

---

- Vim 对于这 4 个命令是支持 `count` 的, 但我们不要求支持.

###### Insert `<Del>` (`2pts`)

这一节要求 Insert 模式下 `<Del>` 的删除行为.

- cursor 指向普通字符 (包含 space) 或 `\t` 时, 删除该字符后 cursor 保持在原来的 Buffer 位置.
  - 后方还有字符时, cursor 因此指向原字符的下一个字符.
  - 删除的是当前行最后一个字符时, cursor 停留在新的行末位置.
- cursor 已经位于当前行行末且存在下一行时, 删除当前行与下一行之间的换行, 将下一行拼接到当前行之后; cursor
  保持在原来的行末位置, 即拼接后下一行原来的第一个字符之前.
- 当前行为一个空行且存在下一行时, 同样删除两行之间的换行并将下一行拼接上来.
- cursor 位于整个文件的最后一个合法位置时, 无效果.

###### `R` (Replace 模式) (`4pts`)

这一节要求 Replace 模式的进入, 输入与退出行为.

- `R`: 从当前光标处进入 Replace 模式, `showmode` 打开时在最下面一行开头显示 `-- REPLACE --`, 退出后清除.
  - Replace 模式中光标的合法位置与 Insert 模式相同: 可以停在某个字符上, 也可以停在行末位置 (行末字符之后); 空行只能停在
    唯一合法位置.
- 输入一个可打印 ASCII 字符 (`0x20~0x7e`) 或 `<Tab>` 时:
  - 光标处有字符时, 用输入的字符替换它; 光标停在行末位置时, 把输入追加到行末 (等价于 Insert 模式).
  - 输入完成后光标自然移动到下一个字符位置 (可能停在新的行末位置); 一个 `<Tab>` 按一个字符处理, 显示规则同选项一节的
    `tabstop`.
  - 替换产生的文本修改与光标移动遵循动作一节的标记规则; 原位替换保留标记, `<CR>` / `<BS>` / `<Del>` 与追加输入造成的
    文本变化按其对应的插入 / 删除规则维护标记; 不写 register.
- 其余功能键:
  - `<CR>`: 在光标位置切分当前行 (不删除任何字符), 光标移到新行的行首, 与 Insert 模式相同.
  - `<Del>`: 按模式切换一节的 Insert `<Del>` 规则删除光标处字符或拼接下一行.
  - `<BS>`: 撤销本次 Replace 模式中最近输入的一个字符, 并把光标左移一个字符位置:
    - 若该字符替换了原字符, 恢复原字符; 若该字符是追加出来的, 删除该字符.
    - 若本次 Replace 模式中没有可撤销的输入, 则只把光标左移一个字符位置 (不修改文本);
      光标可以跨过行首移到上一行的行末位置, 已在文件第一个位置时不移动.
    - 被 `<Del>` 删除的字符不属于输入, 不能被 `<BS>` 恢复.
    - 本次输入的 `<CR>` 所产生的拆行也可以被紧随其后的 `<BS>` 撤销: 重新拼回拆行前的文本,
      不同于没有可撤销输入时仅跨行移动光标. 例如 `abcd` 行首执行 `lR<CR><BS><Esc>`, 文本仍为 `abcd`.
    - `<Del>` 不会清空此前输入的替换恢复记录. 例如 `abcd` 行首执行 `RXY<Del><BS><Esc>`, 结果为 `Xbd`:
      `<Del>` 删除 `c`, 随后的 `<BS>` 把 `Y` 恢复为原来的 `b`, 但不会恢复 `c`.
  - `<Esc>`: 按 Basic Insert 的 `<Esc>` 规则退出到 Normal 模式.
  - 其它按键不在本节要求范围内.
- 一次 `R` 从进入到 `<Esc>` 退出 (或退出前的全部输入) 算一次文本修改 (见撤销与重做一节), 并按重复一节成为 Repeat 记录:
  `.` 会重新进入 Replace 模式并在新位置重放相同的输入.

---

- Vim 支持 `[count]R` (把输入的文本重复 `count` - 1 次), 本项目不要求支持; 也不要求 `gR` (Virtual Replace).

##### 操作 (`23pts`)

本节的删除与复制命令把内容写入 unnamed register (文本与 Characterwise / Linewise 类型), 供 `p` / `P` 与 Register Prefix
使用:

- 写入的命令: `x`, `X`, `D`, `C`, `d{motion}`, `dd`, `y{motion}`, `yy`, `Y`.
  - `x` / `X` / `D` / `C` 均作为 Characterwise; `Y` 与 `yy` 一样为 Linewise.
  - 即使 `[count]D` 或 `[count]C` 的删除范围跨越多行, register type 仍然为 Characterwise. 若 Characterwise range
    跨越行边界, register 中也需要保存这些行边界.
- 一次操作没有产生有效的文本范围时 (空 Characterwise range), unnamed register 保持原内容不变; 例如行首的 `yh` 不改变
  register.
- Linewise 空行仍是有效内容, 会写入包含该空行的 Linewise register.
- 新的写入会完全覆盖之前 unnamed register 中保存的文本和类型.

###### `x` (`2pts`)

这一节要求 Normal 模式下 `x` 的删除行为.

- `x`: 删除 cursor 当前所指字符, 删除后仍处于 Normal 模式.
  - `[count]x`: 删除当前行中从 cursor 开始最多 `count` 个字符, 不跨越换行; `count` 大于 cursor 到当前行行末的字符数时,
    只删除到当前行行末.
  - 当前行为真正的空行时无效果.
- 删除完成后:
  - 删除范围到达当前行行末时, cursor 移动到删除后当前行的最后一个字符.
  - 当前行被删除为空行时, cursor 停留在该行唯一合法位置.

###### `X` (`1pt`)

这一节要求 Normal 模式下 `X` 的删除行为.

- `X`: 删除 cursor 之前的一个字符, 删除后仍处于 Normal 模式.
  - `[count]X`: 删除当前行中 cursor 左侧最多 `count` 个字符, 不跨越换行; `count` 大于 cursor 左侧的字符数时,
    删除当前行中 cursor 之前的所有字符.
  - cursor 已经位于当前行第一个字符, 或当前行为真正的空行时无效果.
- 删除完成后 cursor 向左移动实际被删除的字符数, 并停留在原 cursor 所指字符上.

###### `D` (`2pts`)

这一节要求 Normal 模式下 `D` 的删除行为.

- `D`: 删除从 cursor 当前字符到当前行行末的文本, 包含 cursor 当前字符; 删除完成后仍处于 Normal 模式.
  - `[count]D`: 从 cursor 当前字符开始, 一直删除到向下第 `count` - 1 行的行末; `count`
    大于从当前行到文件末尾的剩余行数时, 删除范围延伸到文件末尾.
  - 与 `[count]$` 一样, 执行前已经在末行且 `count` 大于 1 时命令失败, 不删除文本, 不写 register,
    光标不动; `curswant` 设为极大值.
  - 当前行为真正的空行时, 无 `count` 的 `D` 无效果.
- 删除完成后: cursor 位于删除区域左侧的最后一个字符; 若删除从当前行第一个字符开始, 删除后该行为空, cursor
  停留在该行唯一合法位置. 带 `count` 时规则相同.

###### `C` (`2pts`)

这一节要求 Normal 模式下 `C` 的删除并进入 Insert 行为.

- `C`: 删除的文本范围与 `D` 相同, 但删除后直接从删除范围的起点进入 Insert 模式, 不执行 `D` 删除后的光标左移.
  例如 `abcd` 中光标在 `c` 上执行 `CX<Esc>`, 结果应为 `abX`.
  - 已经在末行且 `count` 大于 1 时, 与 `D` 一样失败, 不进入 Insert 模式.
  - 当前行为真正的空行且有效 `count` 为 1 时, 不删除任何字符, 直接在该行唯一合法位置进入 Insert 模式.
  - `count` 大于 1 时仍按 `D` 的跨行范围删除, 随后从删除范围起点进入 Insert.

###### Toggle Case: `~` (`2pts`)

这一节要求 `~` 的大小写翻转行为.

- `[count]~`: 从当前字符开始, 翻转当前行中最多 `count` 个字符的 ASCII 大小写: `A-Z` 与 `a-z` 互换, 其他字符保持不变但
  同样消耗一次计数; 不跨越换行.
- 光标移动到处理范围之后的字符; 若已处理到行末, 停在本行最后一个字符.
- 空行无效果.
- 该命令不是 `operator`, 不支持 `~{motion}`; 不写 register.
- 全部处理字符都不是字母时可以移动光标, 但不算文本修改.

###### Join: `J` (`3pts`)

这一节要求 `J` 的合并行行为.

- `J` 与 `1J` 均合并当前行和下一行; `[count]J` 合并从当前行开始的 `max(2, count)` 行.
- 行数不足时只合并实际存在的行; 当前行已是末行则无效果.
- 依次把下一行接到当前累计结果后面, 每一步固定采用以下规则:
  1. 删除两行间的换行, 并去掉下一行开头的全部 space / Tab.
  2. 若去掉前导空白后下一行为空, 不添加分隔空格.
  3. 否则, 若累计结果非空, 末尾不是 space / Tab, 且下一行第一个字符不是 `)`, 添加一个 space.
  4. 拼接下一行的剩余内容. 保留累计结果原有的尾部空白, 不因句号, 问号或感叹号添加第二个空格.
- 完成后光标定位在最后一次拼接之前累计结果的字节长度处, 即该次新增分隔空格或新接入内容的开头;
  若此处超出结果的合法字符范围, 限制到行末. 结果为空则停在唯一合法位置.
- `J` 不写 register.

###### `r{char}` (`3pts`)

这一节要求 `r{char}` 的替换行为.

- `[count]r{char}`: 用 `{char}` 替换从光标开始的 `count` 个字符, 完成后仍处于 Normal 模式; `{char}` 可以是一个可打印
  ASCII 字符或 Tab.
  - 从光标到行末的字符数少于 `count` 时, 整个命令失败: 不修改任何字符, 光标与 `curswant` 不变, 不写 register.
  - 成功后光标停在最后一个被替换的字符上, 并把 `curswant` 更新为该位置的显示列.
  - 真正空行上无效果; 替换成一个 Tab 或把 Tab 替换掉时, 一个 Tab 按一个字符计算, 显示规则同选项一节的 `tabstop`.
  - 替换成与原字符相同的字符不算文本修改 (不影响重复一节的 Repeat 记录, 见撤销与重做一节的粒度定义).
  - `r` 不是 `operator`, 不写 register; 原位替换保留标记.
  - 输入的 `{char}` 非法 (例如 `<Esc>` 或其它控制键) 时, 命令取消, 不修改文本.

---

- Vim 中把字符替换成相同字符也会设置 modified; 本项目按重复一节的 saved state 规则以内容为准.

###### `p` / `P` (`6pts`)

这一节要求把 unnamed register 中保存的内容重新插入 Buffer (不改变 register 内容).

- `p`: 在 cursor 之后 `put`. (`3pts`)
- `P`: 在 cursor 之前 `put`. (`3pts`)
- 具体 `put` 行为取决于 register type; 若 unnamed register 为空, `p` 和 `P` 均无效果.

###### Characterwise Put

对于 Characterwise register:

- 当前行为真正的空行时, `p` 与 `P` 都从该行唯一合法位置开始插入.
- 插入时遇到换行需要切分当前文本行, 并按照 register 中保存的行边界恢复对应的多行文本.
- `put` 完成后, cursor 停留在最后一个被插入的字符上; 若最后插入的位置为一个空行, 没有实际字符可以停留, 则 cursor
  位于该空行唯一合法位置.
- 上述光标规则也适用于跨行 Characterwise register 及带 `count` 的 `put`, 是本项目统一采用的行为.

---

- Vim 跨行 `p` / `P` 的默认光标位置可能不同, 本项目仍以这里规定的插入终点为准.

###### Linewise Put

当 unnamed register type 为 Linewise 时, `put` 的位置按照完整文本行确定.

- `p`: 将 register 中保存的所有完整文本行插入当前行之后.
- `P`: 将 register 中保存的所有完整文本行插入当前行之前.
- `put` 完成后, cursor 位于新插入文本的第一行: 该行存在非空白字符时位于第一个非空白字符; 该行只包含空白字符时行为与前文
  `^` 的规则相同; 该行为真正的空行时位于该行唯一合法位置.

###### Put Count

`p` 与 `P` 支持 `count`:

- 对于 Characterwise register, 将 register 中保存的完整文本内容连续插入 `count` 次.
- 对于 Linewise register, 将 register 中保存的完整文本行块连续插入 `count` 次.
- `count` 只重复 register 中保存的内容, 不会在每次重复之间重新计算新的 `put` 位置.
- 整个 `[count]p` 或 `[count]P` 视为一次完整的编辑操作.
- Characterwise Put 完成后, cursor 仍然停留在最后一个被插入的字符上; Linewise Put 完成后, cursor 仍然位于所有新插入文本
  中的第一行, 列位置按照前述 Linewise Put 规则确定.

###### Register Prefix: `"{register}` (`6pts`)

这一节要求显式选择寄存器的前缀 `"{register}`.

- `"` 在 Normal 模式下开始寄存器前缀, 后面紧跟一个寄存器名; 支持 `a-z`, `"` (unnamed) 与 `_` (black hole).
- 要求支持以下三种形式, register 前缀必须位于整条命令的 `count` 之前:
  - `["{register}] [count1] operator [count2] motion`
  - `["{register}] [count1] operator [count2] operator`
  - `["{register}] [count]` 后接 `x` / `X` / `D` / `C` / `Y` / `p` / `P`
- 最后一种形式的可选前缀与 `count` 均作用于所选择的一条命令; 此处 `operator` 仅为 `d`, `y`, `c`, 不包含 Shift.
- 其他前缀顺序不在要求范围内; 在 `count` 或 `operator` 后遇到 `"` 视为非法后续按键并取消整条命令.
- `"` 后的非法名称, 重复的 register 前缀, 前缀后不支持的命令或 `<Esc>` 均取消本条命令, 清空所有待处理前缀, 不改变文本或
  register.
- 各命名 register 独立保存文本和 Characterwise / Linewise 类型, 初始为空; 每次完整覆盖, 不追加.
- 没有显式前缀或使用 `""` 时, 写入与读取均使用 unnamed register.
- 向 `a-z` 写入时同时以同样文本和类型覆盖 unnamed register; 这两个 register 保存独立副本, 以后覆盖 unnamed 不改变命名
  register.
- 向 `_` 写入时丢弃文本, unnamed 与所有命名 register 均不变; 从 `_` `put` 永远无效果.
- 空 Characterwise range 不覆盖任何 register; Linewise 空行仍是有效内容, 与前文规则一致.
- `p` / `P` 从指定 register 读取, 插入范围, `count` 与光标规则和 unnamed `put` 完全相同; 不改变任何 register;
  读取尚未写入的 register 无效果.
- 前缀只作用于当前一条命令. Change 只把删除阶段的旧文本写入目标 register, 后续 Insert 不写入该 register. `~`, `J`, Shift
  与普通 Insert 编辑不写 register.

---

- 不要求大写追加, 数字, 系统剪贴板或表达式寄存器.

##### 范围操作 (`37pts`)

这一节要求实现 Vim Normal 模式中最核心的 Operator-Pending 机制: 输入 `operator` 后, MiniVim 进入 Operator-Pending 状态,
等待后续 `motion` 确定操作范围; `operator` 本身不会立即产生文本修改.

需要支持三个 `operator`:

- `d`: Delete.
- `y`: Yank.
- `c`: Change.

###### Command Grammar

这一节要求支持 `[count1] operator [count2] motion` 语法; 实现 Shift 时, `operator` 还包含 `<` / `>`.

- 若 `operator` 后输入不支持的 `motion`, 应取消当前未完成的命令, 不做修改.

###### Supported Operator Motions (`12pts`)

以下 12 种 `motion` 可以参与 `operator`, 各 1pt: `h`, `j`, `k`, `l`, `w`, `b`, `e`, `0`, `^`, `$`, `gg`, `G`.

- 新增 `motion` 的组合属于后文 Extended Operator Motions, 单独计分.
- Window / Scroll 和设置标记的 `m` 始终不能用于 `operator`.
- `motion` 可以被分成 3 类, 定义如下:
  - **Characterwise Exclusive**: 将 `motion` 的起始位置与目标位置按文本顺序排列后, 操作左端位置到右端位置之前的字符,
    即不包含文本顺序中较后的端点.
  - **Characterwise Inclusive**: 将 `motion` 的起始位置与目标位置按文本顺序排列后, 操作两个端点以及它们之间的所有字符.
  - **Linewise**: 操作 `motion` 起始位置与目标位置所在行之间的**所有**完整文本行, 包含起始行与目标行.
- 例: 某行文本为 `abcd`, 光标在 `c` 时执行 `dh`: 起始位置是 `c`, 目标位置是 `b`, 按文本顺序排列后为 `[b, c]`; 由于 `h`
  是 Exclusive, `c` 不包含在内, 实际区间为 `[b]`, 对该区间执行删除; 删除后文本为 `acd`, 光标仍在 `c`.

###### Motion Type

对于 Characterwise Exclusive, Characterwise Inclusive 与 Linewise range, 除特殊说明均按照前文定义计算最终操作范围.

- `h`: Characterwise Exclusive.
  - 若 cursor 位于行首, `h` 无法产生非空范围, 因此无效果.
- `l`: Characterwise Exclusive.
  - cursor 位于行尾时, `l` 对最后一个字符有效.
- `[count]h` / `[count]l`: 不跨越行, `count` 过大时范围分别限制到当前行行首或行末.
- `w`: Characterwise Exclusive.
  - `w` 与 `operator` 组合时存在一个特殊的行尾行为: 若最后一次 `w` 所经过的最后一个 word 位于某一行的行末,
    则操作范围结束在该 word 的最后一个字符, 不继续包含换行以及下一行第一个 word.
  - 例如 `hello` 与 `world` 两行中, cursor 位于 `hello` 的 `h` 时执行 `dw`, 只删除 `hello`, 不删除两行之间的换行.
- `b`: Characterwise Exclusive.
- `e`: Characterwise Inclusive.
- `0`: Characterwise Exclusive.
- `^`: Characterwise Exclusive.
- `$`: Characterwise Inclusive; 执行前已在末行且有效 `count` 大于 1 时失败, `d` / `y` / `c` 均不执行操作.
- `j`: Linewise.
  - 若 `count` 过大, range 延伸到文件最后一行; 若 `j` 已经在文件最后一行, 则对应 `operator` 无效果.
- `k`: Linewise.
  - 若 `count` 过大, range 延伸到文件第一行; 若 `k` 已经在文件第一行, 则对应 `operator` 无效果.
- `gg`: Linewise; 即使目标行就是当前行, 仍然产生包含当前整行的 Linewise range.
- `G`: Linewise; 即使目标行就是当前行, 仍然产生包含当前整行的 Linewise range.

---

- `motion` 在 Operator-Pending 状态下只用于确定操作范围; 不应该将 `motion` 后的目标位置当成 `operator` 执行完成后的最终
  cursor 位置.
- 若 `motion` 的 `count` 超过能够移动的范围, 则按照动作一节中该 `motion` 的边界行为确定最终范围.
- 除 `w` 的行尾规则与 `cw` 的特殊规则外, MiniVim 不要求实现 Vim 对跨行 Exclusive `motion` 的其他自动 Inclusive /
  Linewise 转换.

###### Extended Operator Motions (`4pts`)

以下 `motion` 组合单独计分, 各 1pt: Find (含 `;`), Match, Mark Jump, Search (含 `n`, `N`).

- `f{char}` / `t{char}`: Characterwise Inclusive.
- `F{char}` / `T{char}`: Characterwise Exclusive.
- `;`: 沿用所记录查找种类的上述类型.
- 无显式 `count` 的 `%`: Characterwise Inclusive.
- 有显式 `count` 的 `%`: Linewise.
- 标记精确跳转 (如 `` `a ``): Characterwise Exclusive.
- `/...<CR>` / `?...<CR>` / `n` / `N`: Characterwise Exclusive.
- 以上类型均按本项目 "先按文本顺序排列端点" 的定义计算, 不额外套用 Vim 的跨行 Exclusive 转换规则.
- 无 `count` 的 `d%` 以执行前的光标为起点, 配对括号为终点; 向右寻找候选括号的过程不改变起点.
- `d50%` 与 `50d%` 均使用显式 `count` 50 的百分比跳转; `operator` 两侧任意一侧有 `count` 就视为显式输入,
  有效值仍按相乘规则计算.
- 标记跳转忽略有效 `count`; 其他查找和搜索使用有效 `count`; `;` 不再乘上查找记录中的旧 `count`.
- 若 `motion` 失败, 整条 `operator` 命令不修改文本, 不移动光标, `c` 也不进入 Insert, register 不变.
- 完整查找或搜索对记录的更新仍遵循动作一节中查找与搜索的规则.
- 若 `motion` 成功但位移为零, 按类型计算范围: Inclusive 包含当前字符 (空行则无字符), Exclusive 为空, Linewise
  包含当前整行.
- 因此相邻目标上的 `dt{char}` 可以删除当前字符; 跳回当前位置的搜索产生空 Exclusive range, `c` 按前文空范围规则
  进入 Insert.
- 搜索发生环绕时, `operator` 只取原位置与最终目标之间按文本顺序排列的单个区间, 不取环绕路径, 不重复处理经过多次的文本
  (课程规则).
  - 例: 从第二行搜索并环绕到第一行时, 最终操作区间仍是第一行目标到第二行原位置之间的 Exclusive 区间.

###### Doubled Operator

相同 `operator` 连续输入两次表示对完整文本行进行操作:

- `dd`: 删除当前行.
- `yy`: `yank` 当前行.
- `cc`: `change` 当前行.
- Doubled Operator 为 Linewise 操作.
- 同样支持 `[count1] operator [count2] operator` 的形式 (`count` 规则见 Command Grammar).

###### Delete (`4pts`)

这一节要求 `d` 的删除行为.

- `d{motion}`: 删除 `motion` 所确定的 range, 删除完成后保持 Normal 模式.
  - Characterwise range: 删除完成后 cursor 位于被删除范围的起始位置; 若该位置在删除后仍存在字符, cursor 停留在该字符上.
    若删除范围一直延伸到当前行行末, 使 range 起始位置后不存在字符, 则 cursor 移动到该行最后一个字符; 若该行删除后成为
    空行, cursor 停留在该行唯一合法位置.
  - Linewise range: 删除范围内的完整文本行. 删除后若原删除范围下方仍有文本行, cursor 移动到该行第一个非空白字符;
    若删除范围一直到文件末尾, cursor 移动到新的最后一行的第一个非空白字符; 若文件中的所有行均被删除, Buffer 中仍然保留
    一个空行 (注意在合适的地方调用 EnsureNonEmpty), cursor 位于该行唯一合法位置.
  - 被删除的文本写入 unnamed register, 并保留本次删除的 Characterwise / Linewise 类型 (见操作一节的写入规则).

###### Yank (`6pts`)

这一节要求 `y` 的复制行为.

- `y{motion}`: 将 `motion` 所确定的 range 按照类型复制到 unnamed register.
  - Characterwise range: 完成后光标位于被复制范围在文本顺序中的起始位置.
  - Linewise range: 向后复制时保留原光标位置; 向前复制时回到对应 `motion` 的目标位置,
    不因范围是完整行就额外把列重置为 0. 目标列遵循该 `motion` 的规则, 并限制在目标行的合法字符位置.
  - `yy` 与 `[count]yy` 复制从当前行开始的完整文本行, 行数不足时截断到文件末尾; 光标保持原位.
    例如 `  abc` 上第 4 列执行 `yy` 后仍在第 4 列; `abcd` / `efgh` 上第一行第 3 列执行 `yj` 后仍在原位.
- `[count]Y`: 与 `[count]yy` 完全等价: 把从当前行开始的 `count` 行以 Linewise 类型复制到 unnamed register
  (见操作一节的写入规则), 光标保持原位不动.
  - `Y` 之后输入的按键是一条新的命令.
  - `Y` 与 `yy` 一样写入 unnamed register (Linewise), 并支持 Register Prefix.

---

- 若不实现 `p` / `P` 等使用 register 的功能, 这里只要保持 cursor 位置正确即可.

###### Change (`4pts`)

这一节要求 `c` 的删除并进入 Insert 行为.

- `c{motion}`: 首先删除 `motion` 所确定的 range, 随后进入 Insert 模式.
  - Characterwise range: 删除后直接在 range 起始位置进入 Insert 模式; 若 range 为空, 不删除文本, 直接在当前位置进入
    Insert 模式.
  - Linewise range: 删除范围内的完整文本行, 在原范围位置保留一个空行, 并在该空行唯一合法位置进入 Insert 模式.
- 空 Characterwise range 进入 Insert 是课程规定, 例如文件开头的 `cb` 应进入 Insert, 即使默认 Vim 对该操作不进入 Insert.
- 这不改变前文明确规定的 `motion` 失败行为: 文件末行的 `cj`, 文件首行的 `ck`, 以及文件末行失败的 `c2$` 均无效果, 不进入
  Insert.
- 删除的原文本同样写入 unnamed register, 并保留 Characterwise / Linewise 类型 (见操作一节的写入规则).

###### `cw` Special Case

`cw` 是 `c{motion}` 的特殊情况.

- 执行 `cw` 时 cursor 位于非空白字符上时, `change` 范围结束在当前 word 的末尾, 而不是普通 `w` 所指向的下一个 word 开头.
  - 带 `count` 时, 最后一个被 `change` 的 word 后面的空白同样不属于操作范围.
- cursor 当前位于空白字符上时, `cw` 不使用上述特殊行为, 而按照普通 `w` 产生的 range 执行 Change.

###### Shift: `<` / `>` / `<<` / `>>` (`3pts`)

这一节要求缩进命令 `<` / `>` (含 doubled 形式) 的行为.

- `>{motion}` / `<{motion}`: 将 `motion` 对应的文本行向右 / 向左缩进一级.
- `>>` / `<<`: 处理当前行.
- `[count1]>[count2]>` 等 doubled 形式: 向下处理有效 `count` 行, 超过末行时截断.
  - `operator` 两侧 `count` 的乘积决定 `motion` 的范围或 doubled 形式的行数, **不决定缩进级数**.
- 先按对应 `motion` 的规则得到 range, 再处理该 range 中实际包含字符或换行的所有文本行:
  - Exclusive range 若终点恰为较后行的第 0 列, 不包含该终点行; Linewise range 包含其中所有行, 包括空行.
  - `motion` 失败或 Characterwise range 为空则无效果.
  - 支持的 `motion` 与本次实现的 `d` / `y` / `c` 相同; 新增 `motion` 组合仍依赖对应扩展项.
- 固定每级 4 个显示列. 对每个受影响的非空行, 计算原行首连续 space / Tab 的显示宽度 `W` (Tab 的宽度按制表位选项
  `tabstop`, 默认 4 列):
  - 右移后的前导空白统一替换成 `W + 4` 个 space.
  - 左移后的前导空白统一替换成 `max(0, W - 4)` 个 space.
  - 真正空行保持为空; 只有空白的非空行也按上述宽度规则处理.
  - 非前导空白和正文完全不变. 只剩 1 到 3 列缩进时, 左移会全部移除.
- 成功得到至少包含一行的范围后, 光标移到第一条受影响行, 列位置遵循 `^` 的规则, 即使该次没有改变文本. 不写 register.

---

- 不要求保留原 Tab 字节.

##### 重复 (`6pts`)

这一节要求记录最近一次可重复的完整文本修改. `.` 也不是恢复某份旧 Buffer 快照: 它应从当前位置重新执行上一次编辑的意图.

###### Repeat Unit

下列完整命令可以成为一条 Repeat 记录:

- Basic 的 `i` / `a` 及模式切换一节的 `I` / `A` / `o` / `O` 所开始的完整 Insert session.
- 操作一节的 `x`, `X`, `D`, `C`, `~`, `J`, `r{char}`, 模式切换一节的完整 `R` session, 范围操作一节的 `d` / `c` 与
  doubled `operator`, 操作一节的 `p` / `P`, 以及 Visual 模式中会修改文本的操作.
- 若同时实现范围操作一节的 Shift, 扩展 `operator` 可用的 `motion` 或操作一节的 Register Prefix, 对应编辑同样可以重复.

---

从进入 Insert 到对应 `<Esc>` 返回 Normal, 中间普通字符, `<Tab>`, `<CR>`, `<BS>` 与 `<Del>` 都属于同一 session;
记录进入方式和后续输入动作, 重复时在新位置重放这些动作, 不能只记录最后新增的字符串.

- 通过 `c` 或 `C` 进入 Insert 时, 删除范围的命令与整个 Insert session 合为一条记录.
- 单独 `o` / `O` 即使随后立即 `<Esc>`, 只要新增了空行仍是文本修改.
- 普通 Insert 与 Insert Entry 本身仍不要求 `count`; 对这些记录执行 `[count].` 时忽略 `count`, 只重放一次 session.
- 只有命令完成后完整 Buffer 内容与命令开始前不同, 才替换 Repeat 记录; Change 的比较起点在删除之前.
- 因此失败命令, 空范围 `delete`, 纯光标移动, 处理非字母的 `~`, 以及输入后全部删回的净零 Insert session 都不覆盖旧记录.
- 净零 session 中的标记, 查找或 register 副作用按各自规则保留, 不回滚.
- 普通 `motion`, 搜索, `m`, `yank`, 窗口命令, 保存, 以及 `u` / `<C-r>` 与一次宏播放的 `@` / `Q` 命令本身都不覆盖 Repeat
  记录 (宏内部的修改按各自的规则覆盖).
- 文件刚打开时记录为空.

###### Repeat Count

`.` 在当前位置执行记录, 默认使用记录中上一次成功修改的有效 `count`.

- 没有记录时无效果.
- `[count].` 用新的有效 `count` **替换** 原 `count`, 不表示把整条旧命令运行 `count` 次.
  普通 Insert session 的例外见 Repeat Unit; Visual 修改的例外见 Visual 一节, 两者均忽略这里的新 `count`.
- 对于 `[count]operator[count]motion`, 替换的是两侧 `count` 相乘后的有效值; 原来是否显式 `count` 的信息在无新 `count`
  时保留, 有新 `count` 时置为显式.
- 重复产生实际文本修改后, 记录保留本次采用的有效 `count`, 因而 `4.` 成功后下一次 `.` 继续采用 4.
- 若重复失败或净修改为零, 原记录 (含旧 `count`) 保持不变.
- 重复仍是一条编辑命令, 不能把 `.` 本身记录成递归调用 `.` 的记录.

---

- `c` / `C`: 新 `count` 只控制删除范围, 随后的 Insert session 重放一次.
- `J`: 新 `count` 仍表示合并的总行数, 最少两行.
- `p` / `P`: 新 `count` 表示内容重复插入的次数.
- Shift: 新 `count` 控制 `motion` 或 doubled 形式的行数, 不控制缩进级数.
- 忽略 `count` 的 `motion` (例如标记跳转) 重复时仍忽略 `count`.

###### 重放时的状态

- Normal 编辑中的普通 `motion` 在新位置重新计算范围; 不记住旧绝对范围或旧删除文本. Visual 编辑按 Visual 一节记录
  选区大小而不是重放旧 `motion`. 重放 Insert session 时 `<BS>` / `<Del>`
  也按新位置的边界规则执行.
- `p` / `P` 读取执行 `.` 当时指定 register 的内容, 不冻结原 `put` 的文本. 无前缀时读取当前 unnamed; 有前缀时记住
  register 名称.
- 带 register 前缀的 `delete` / `change` 重复时仍写同一目标, 默认命令仍写 unnamed. 不支持直接给 `.` 再加 register 前缀.
- 对显式 `f` / `F` / `t` / `T` 构成的编辑, 记录命令种类与输入字符; 重放时重新执行该查找, 并按 Find 规则更新查找记录.
- 对 `;` 构成的编辑, 记录的是重复查找命令 `;`, 不冻结当时的查找字符. `.` 使用执行当时的字符查找记录,
  并保留 `t` / `T` 重复时排除相邻匹配的规则. 例如从 `a,b.c,d.e` 行首执行 `f,0d;f..`, 最后应得到 `be`:
  最后的 `.` 重复 `d;`, 此时 `;` 使用最近的句点查找, 而不是先前的逗号查找.
- 对 `/`, `?`, `n`, `N` 构成的编辑, 记录当时实际使用的字面串和方向.
- 搜索编辑仍固定记录当时的字面串和方向, 后续修改搜索记录不影响其重复含义 (课程规则); 重放不覆盖用户当前的搜索记录.
  这一冻结规则不适用于上述字符查找 `;`. 标记跳转则记录标记名,
  重复时读取该标记的当前位置; 标记失效时失败.
- 其他边界, 空范围, register 写入, 标记维护和光标位置均遵守被重放命令本身的规则.

###### Saved State

保存不清除 Repeat 记录; 成功保存后, 当前 Buffer 内容成为新的 saved state. 任何编辑 (包括 `.`) 完成后, modified
应表示当前 Buffer 内容是否与最近一次成功保存的内容不同; 初始 saved state 为刚打开的 Buffer 内容.

- 若最终文本恢复为 saved state, modified 为 false; 否则为 true.
- 不得仅因执行过某条编辑命令就永远保持 modified 为 true.

##### 撤销与重做: `u` / `<C-r>` (`12pts`)

`u` 撤销最近一次修改, `[count]u` 一次撤销最近 `count` 次修改; `<C-r>` 重做最近一次被撤销的修改, `[count]<C-r>` 一次重做
`count` 次.

- 没有可撤销 / 可重做的修改时命令无效果; `count` 超过历史长度时停在历史的端点, 不得为超大 `count` 实际循环.

###### 修改的粒度

一次 "修改" 是一条完整命令造成的文本变化, 粒度与重复一节的记录单位相同 (见该节 Repeat Unit); 一次命令即使修改多处文本也
整体算一次修改.

- 一次宏播放 `[count]@{register}` / `[count]Q` 整体算一次修改, 即使宏内部包含多条修改.
- 光标移动, 搜索, `m`, `yank` (`y` / `Y`), 窗口命令, 保存, `:set` 等不进入撤销历史.
- 内容没有变化的命令 (例如空 range 的 `d`, 同字符的 `r`) 不产生修改.

###### 效果与状态

- 撤销 / 重做直接恢复 / 重新应用文本内容; 光标恢复遵循对应编辑命令在 Vim 中的撤销 / 重做规则,
  不统一推导成底层第一个被删除字节的位置. 历史记录应同时保留文本与必要的光标恢复信息;
  若恢复位置超出当前 Buffer 的合法范围, 则限制到对应行末或空行的唯一位置.
  - `J` 的撤销恢复合并前的光标位置. 例如从 `abc` / `def` 第一行第 1 列执行 `Ju`, 恢复两行后光标在第 1 列,
    而不是根据被删除换行的位置移到第 3 列.
  - Insert session 在插入起点恢复光标. 例如 `abcd` 中在 `c` 前插入 `XY` 后退出, 再执行 `u` 或随后 `<C-r>`,
    光标均在第一行第 3 列. 不要求用同一个「原光标」规则替代所有编辑命令的恢复语义.
- 撤销 / 重做不改变 register: `u` 不会把已删除的文本从 register 中清除或写回, register 保持撤销前的状态.
- 文本改写按动作一节的标记规则平移; 因为删除而失效的标记不会因撤销而恢复 (课程规则, 与 Vim 不同).
- `u` / `<C-r>` 本身不成为 Repeat 记录, 也不覆盖现有记录: 例如 `xu` 之后 `.` 仍然重复 `x` (见重复一节).
- 撤销后如果执行了新的修改, 原来的重做历史被丢弃; 只进行移动 / 搜索 / `yank` 等不产生修改的操作不会丢弃重做历史.
- modified 按重复一节的 Saved State 规则更新: 撤销 / 重做后重新与最近一次成功保存的内容比较, 相同则为 false.
- 保存文件不清空撤销历史.

---

- 不要求 `U` (行撤销), `:undo` / `:redo` 指令, 以及撤销树 / 分支等高级功能.

##### 宏: `q` / `@` / `Q` (`11pts`)

###### 录制: `q{register}` ... `q` (`4pts`)

`q{register}` 开始把随后输入的所有按键录制到寄存器 `{register}` 中 (`{register}` 取 `a-z`); 录制期间这些按键会像平时一样
正常执行. 回到 Normal 模式且没有尚未完成的命令时, 按 `q` 停止.

- 用于停止的 `q` 以及开始录制的 `q{register}` 本身不会被录制.
- 录制期间输入的普通字符, `<Esc>`, `<CR>`, `<BS>`, `<Del>`, `count`, register 前缀等按键都按原样记录 (记录的是按键序列,
  而不是按键造成的结果).
- 录制期间按 `<Esc>` 会像平时一样执行 (结束 Insert, 打断未完成的命令) 并被记录, 但不会停止录制.
- 只有作为 Normal 命令的 `q` 才停止录制. Insert / Replace / Command-line 中输入的 `q`, 以及 `fq` 或 `rq` 中的参数
  `q`, 都照常执行并被记录, 不会停止录制. 宏播放产生的 `q` 不启动或停止录制.
- 录制结束后, 目标寄存器保存完整的按键序列文本, 类型为 Characterwise.
- 录制不改变 unnamed register (这一点与 Register Prefix 中向 `a-z` 写入的规则不同), 也不改变其它寄存器.
- 若 `{register}` 不是 `a-z` (或在输入寄存器名前取消), 命令取消, 不开始录制.

###### 播放: `@{register}` (`5pts`)

`@{register}` 把寄存器 `{register}` (`a-z`) 中保存的文本当作按键序列重新执行; `[count]@{register}` 连续执行 `count` 次.

- 寄存器为空 (未录制或未写入) 时无效果.
- `@` / `Q` 本身不改写任何寄存器; 宏内部的命令按其自身规则读写 register.
- 播放中的每个按键都按它当前的含义执行: 宏里可以包含 `count`, register 前缀, Insert 输入, 执行其它寄存器的 `@`
  (嵌套播放), 也可以包含 `u`, `.`, `p` 等命令.
- 播放过程中遇到报错的命令时, 中断剩余宏按键及尚未执行的重复次数; 这也包括文件末行的 `j` 等移动失败,
  不能仅把非法命令视为中断条件. 已经完成的编辑不回滚; 成功但没有文本修改的命令不因此中断宏.
  例如单行 `abc` 的行首播放 `jiX<Esc>`, `j` 失败后不再执行 `iX<Esc>`, 文本仍为 `abc`.
- 一次 `[count]@{register}` 可被一次 `u` 撤销 (见撤销与重做一节); 其中的文本修改按重复一节规则更新 Repeat 记录, 因而 `.`
  通常重复宏中最后一次文本修改.

###### `Q` (`2pts`)

`[count]Q` 播放最近一次用 `q{register}` 录制到的寄存器, 即录制结束时的那个寄存器.

- 之后播放过别的寄存器不改变 `Q` 的目标; 没有录制过任何宏时 `Q` 无效果.
- `Q` 的播放, `count`, 错误处理与 `@` 完全相同.

###### 宏与 register

- 宏寄存器与普通寄存器共用一套存储: `"ap` 会把宏的按键序列文本粘贴进 Buffer (控制字符按普通字符插入),
  修改后的寄存器内容也可以再被 `@` 播放 (寄存器类型不影响播放).

---

- 不要求支持大写寄存器的追加录制 (`qA` 等), 数字 / 特殊寄存器 (`q1`, `q"` 等) 的录制.
- 不要求支持递归播放自身等特殊情况的处理.
- 不要求 `@@`, `@:`, `@=` 等特殊形式.
- Vim 自身的 `Q` 是 Ex 模式; 本项目采用与目录描述一致的语义 (播放最近录制的寄存器, 与 Neovim 的 `Q` 相同).

#### Visual 模式 (`10pts`)

本节只要求字符级 Visual 模式 (`v`), 不要求 `V` (Linewise Visual) 与 `<C-v>` (Blockwise Visual).

##### 进入, 移动与退出

`v` 从当前位置进入 Visual 模式: 当前光标位置同时作为选择的锚点 (anchor) 与当前端点, 初始选择只包含光标当前所在的字符;
移动命令通常与 Normal 模式一致 (支持 `count`, 遵循 `curswant` 等), 但 Visual `$` 的行尾位置按下文单独处理.

- Visual 模式中光标通常停留在字符上; `$` 允许端点停在行末字符之后的位置, 用于选择行尾换行. 空行使用唯一的位置.
- `showmode` 打开时 (默认), 最下面一行开头显示 `-- VISUAL --`, 退出后清除.
- 再按 `v` 或 `<Esc>` 退出到 Normal: 不修改文本, 保留当前端点位置; 若端点在末字符之后, 限制到本行最后字符,
  空行仍停在唯一位置. 不像 Insert 的 Esc 那样对普通字符位置额外左移.
- `o` 把光标移到选择的另一端 (anchor 处), 选择范围不变; 再按 `o` 移回.

---

- `v` 前的 `[count]` 不作要求 (按无 `count` 处理).

##### 选择范围

把 anchor 与当前端点按文本顺序排列为 `[start, end]`, 则 Characterwise 选择是闭区间 `[start, end]`: 包含两个端点在内的
所有字符; 选择跨行时, 两个端点之间的换行符也包含在范围内.

- 例: 在 `ab` / `cd` / `ef` 三行中, 从第一行行首执行 `vj` 的选择内容是 `ab`, 换行, `c`.
- `$` 使选择的一端停在最后字符之后, 将行尾换行纳入选择; 不能只在最后字符上附加一个换行标记而忽略端点位置.
  从该位置按 `h` 会回到最后字符, 不再包含该端的换行. 垂直移动保留行尾期望时, 端点仍可停在目标行的行尾之后.
  - 例: `abc` / `def` 上从 `a` 执行 `v$y`, register 为 `abc\n`; `vlly` 与 `v$hy` 都复制 `abc`, 不带换行.
  - 同一初始状态执行 `v$h<Esc>`, 光标停在 `c` (第 3 列), 而不是 `b`.
  - 端点已经在行尾之后时, `l` 不再向右移动, 也不跨到下一行; `v$ly` 仍复制 `abc\n`.
- 真正空行需要区分位置: 空行后还有文本行时, 该位置可选中换行. 例如空行 / `abc` 上执行 `vd`, 删除首个空行,
  register 为 Characterwise 的 `\n`; 执行 `vy` 则只复制该换行, 不改文本.
- 文件末尾空行没有后续行分隔符: 例如 `abc` / 空行上执行 `Gvy`, 未命名 register 被覆盖为空 Characterwise 字符串,
  不是保留旧值. 这属于 Visual yank 的特例, 不改变 Normal 空范围 operator 的寄存器规则.
- 整个 Buffer 只有一个空行时, `vd` 不修改文本, 也不覆盖 register. 对确实为空的选择执行 `c` 时,
  按课程的空 Characterwise Change 规则进入 Insert. 不得将所有空行选择都按同一种空范围处理.

##### 对选择执行操作

在 Visual 模式中执行下列命令时, 命令作用于当前选择范围, 完成后退出 Visual 模式:

- `d` / `x`: 删除选择范围, 按操作一节的写入规则写入 register. (`2pts`)
  - 完成后光标位于选择范围在文本顺序中的起点.
- `y`: 复制选择范围到 register, 不修改文本. (`1pt`)
  - 完成后光标位于选择范围在文本顺序中的起点.
- `c`: 删除选择范围, 按范围操作一节的 Change 规则进入 Insert 模式. (`2pts`)
  - 完成后光标位于选择范围在文本顺序中的起点.
- `~`: 翻转范围内字符的大小写 (非字母保持不变). (`1pt`)
  - 不写 register; 完成后光标位于选择范围起点, 并按该位置更新 curswant.
- `U`: 范围内字符转为大写. (`1pt`)
  - 不写 register; 完成后光标位于选择范围起点, 并按该位置更新 curswant.
- `u`: 范围内字符转为小写 (Visual 模式下 `u` 不是撤销). (`1pt`)
  - 不写 register; 完成后光标位于选择范围起点, 并按该位置更新 curswant.
- `r{char}`: 把范围内每个字符替换为 `{char}`. (`1pt`)
  - 只替换文本字符, 不把选中的行分隔符替换成 `{char}`, 不合并或新增文本行.
    例如 `ab` / `cd` 上从第一行行首执行 `v$jrX`, 结果是 `XX` / `XX`, 而不是把换行也替换成 `X`.
  - 不写 register; 完成后光标位于选择范围起点, 并按该位置更新 curswant.
- `J`: 按操作一节的 `J` 规则连接选择范围覆盖到的所有行. (`1pt`)
  - 选择只覆盖一行时仍尝试合并该行与下一行, 不是无效果; 已在末行则无效果.
    例如 `abc` / `def` 上从第一行行首执行 `vJ`, 结果为 `abc def`, 光标在分隔空格上 (第 4 列).
  - 光标位置也按操作一节的 `J` 规则确定.
- `p` / `P`: 用 register 内容替换选择范围, 见下一节.
- `>` / `<`: 若实现了范围操作一节的 Shift, 对选择范围覆盖到的完整行向右 / 左缩进, 规则与 Shift 相同.
  - 光标位置也按 Shift 规则确定.
- 这些命令中只有会改变文本的命令才按重复一节替换 Repeat 记录.
  - Visual 修改的 `.` 保存选区大小与操作, 不重新执行当初的移动命令. 单行选区重用字符数;
    跨行选区重用行数与末行端点列; 以 `$` 延伸的选区保留延伸到行尾的含义. 新范围以当前光标为起点,
    超出 Buffer 时限制到实际存在的文本. 对 Visual 修改的 `[count].` 不另行扩大范围.
  - 例: `ab cd` / `abcdefgh ij` 从第一行行首执行 `vedj0.`, 两行结果为 ` cd` / `cdefgh ij`:
    第二次删除的是上次选区的 2 个字符, 而不是重新执行 `e` 删除整个新 word.

##### Visual 模式下的 `p` / `P`

`p` / `P` 用 register 内容替换选择范围, 与 Vim 相同 (可以理解为先把 register 内容放到选择范围的终点之后,
再删除选择范围):

- register 为 Characterwise 时, 在范围起点插入 register 文本再删除范围, 即直接替换.
- register 为 Linewise 时, 把 register 中的完整行放在选择范围终点之后 (可能拆开终点所在的行), 再删除选择范围.
- `p` 把被替换的选择范围文本以 Characterwise 类型写入 unnamed register (替换后用 `p` 取回的是刚被删掉的选区文本); `P`
  不改变任何 register.
- 完成后光标按操作一节中对应 `put` 的规则定位 (Characterwise 为最后一个被插入的字符, Linewise 为新插入文本的第一行),
  而不是范围起点.
- `p` / `P` 同样按重复一节成为 Repeat 记录; 因为 `p` 已把 unnamed register 换成被删除的选区文本, 之后 `.`
  重复时使用的是改变后的 register.

##### 与 Normal 模式功能的对应

Normal 模式中的大部分功能在 Visual 模式下都有一个 "作用于当前选择范围" 的对应版本: 写法与 Normal 相同, 只是作用范围由
`motion` 改为当前选择.

- 动作一节的各类移动 (支持 `count`): 通常以相同规则移动选择的当前端点; `$` 的行尾之后位置按本节的选择规则处理.
- 动作一节的字符查找与搜索: 与 Normal 相同, 只移动端点.
- 范围操作的 `d{motion}` / `dd` / `D`: `d` / `x` 删除选择范围.
- 范围操作的 `y{motion}` / `yy` / `Y`: `y` 复制选择范围.
- 范围操作的 `c{motion}` / `cc` / `C`: `c` 删除选择范围并进入 Insert.
- 操作的 `x` / `~` / `r{char}` / `J`: `x` / `~` / `r{char}` / `J`.
- 操作的 `p` / `P`: `p` / `P` 替换选择范围.
- 范围操作的 `>{motion}` / `<{motion}`: `>` / `<` 缩进选择范围覆盖到的行.
- 模式切换的 `i` / `a` / `I` / `A` / `o` / `O`: 没有直接对应; 需要进入 Insert 时用 `c`.
- 撤销与重做的 `u` / `<C-r>`: 没有对应 (Visual 模式的 `u` 是转小写).
- 重复一节的 `.`: 会修改文本的 Visual 操作按重复一节被 `.` 重放.
- 读写 register 的规则与 Normal 一致 (见操作一节的写入规则).
- `<Esc>`: 退出 Visual 模式, 光标停在当前端点.

##### 不要求的内容

- 不要求 `"a` / `"_` 等 Register Prefix 与 Visual 命令的组合, 也不要求 Visual 中 `operator` 前带 `count` 的写法 (Vim
  用它表示 `>` / `<` 的缩进级数等).
- 不要求 `gv`, Visual 模式下的 `:`, 文本对象 (`iw` / `a"` 等), 以及上表之外的 Visual 命令 (`D`, `X`, `Y`, `C`, `S`, `s`,
  `R`, `=`, `!`, `gq` 等).

#### Command-line 模式

##### 指令 (`12pts`)

`:e` 影响动作一节的标记与撤销与重做一节的撤销历史.

指令名按 Vim 的方式缩写, 即命令名必须完整输入或使用其前缀: `:w`, `:wr`, `:wri`, `:writ`, `:write` 等价; `:q`, `:qu`,
`:qui`, `:quit` 等价; `:e`, `:ed`, `:edi`, `:edit` 等价; `:se`, `:set` 等价; 命令名大小写敏感 (`:W` 不等价于 `:w`).

- 指令名与参数之间由一个或多个空白分隔, 参数从指令名后的第一个非空白字符开始.
- 无法识别的指令, 参数个数 / 形式不合法的指令, 整条指令不执行, 当前状态不变 (可以显示错误信息, 不要求文本与 Vim 一致; 与
  Basic 对非法指令的处理相同).

###### `:w[rite] [file]` (`4pts`)

把整个 Buffer 内容写入文件.

- 省略 `[file]`: 写入当前文件名对应的文件; 若当前 Buffer 没有文件名, 指令失败 (无效果).
- 指定 `[file]`: 写入该路径, 文件不存在时创建. 与 Basic 的 `:wq [file]` 一致, 若文件已存在直接覆盖原有内容, 本项目不要求
  `!` (Vim 默认会以文件已存在为由拒绝写入, 这是课程简化).
- 写入成功后: 当前 Buffer 内容成为新的 saved state (modified 变为 false, 见重复一节); 若 Buffer 原本没有文件名, 把
  `[file]` 作为新的当前文件名; 若已有文件名, 当前文件名不变.
- 写入失败 (例如路径不可写) 时保持原状态, modified 不变.

---

- Vim 在写入不同文件名时不会清除 modified (它把保存状态绑定在当前文件上); 本项目按重复一节的 saved state 规则以内容为准.

###### `:q[uit][!]` (`2pts`)

退出 MiniVim.

- `:q`, `:quit`: 当前 Buffer 有未保存修改 (modified 为 true) 时指令失败并保持运行; 否则退出.
- `:q!`, `:quit!`: 不检查修改, 直接退出 (与 Basic 相同).

###### `:wq [file]` (`2pts`)

先执行 `:w [file]`, 写入成功后退出 MiniVim; 写入失败 (或没有可写的文件名) 时保持运行.

###### `:e[dit][!] [file]` (`4pts`)

打开文件, 用文件内容替换当前 Buffer.

- `:e [file]` / `:e! [file]`: 打开 `[file]`; 不带 `!` 时, 若当前 Buffer 有未保存修改, 指令失败.
- `:e` / `:e!` (省略 `[file]`): 从磁盘重新读取当前文件; 当前 Buffer 没有文件名时指令失败.
- `[file]` 不存在时按新文件处理: 得到一个只含一个空行的空 Buffer, 当前文件名设为 `[file]`; 此时不创建磁盘文件 (与 Vim
  一致).
- 打开文件后: 光标位于第 1 行第 0 列, 视口顶部为第 1 行, modified 为 false; 撤销 / 重做历史清空, 全部标记失效; Repeat
  记录不受影响.

---

- Vim 在重新打开同一文件 (`:e` / `:e!` 省略参数) 时会保留标记与撤销历史, 且光标保持原来的行号; 本项目统一按上一条重置,
  以保持行为简单一致.

##### 选项 (`16pts`)

###### `:se[t] ...` (`16pts`)

选项是编辑器运行时可以调整的设置. 例如 `:set tabstop=8` 改变 Tab 的显示宽度, `:set noshowmode` 关闭底部模式提示.
本项目只要求 `tabstop` 和 `showmode` 两个选项, 不要求实现 Vim 的其他选项或字符串选项.

- `:set showmode` 打开模式提示, `:set noshowmode` 关闭模式提示.
- `:set {option}?` 查询当前值. 布尔选项显示 `showmode` 或 `noshowmode`, 数字选项显示 `tabstop={value}`.
  `:set tabstop` 也表示查询, 不是赋值.
- `:set showmode!` 将开关取反; `!` 不能用于数字选项.
- `:set {option}&` 将指定选项恢复为本项目的默认值; `:set all&` 恢复全部两个选项.
- `:set tabstop={value}` 设置制表位宽度. 布尔选项不接受 `={value}`.
- `:set` 显示与默认值不同的选项, `:set all` 显示全部两个选项. `:set!` 和 `:set! all` 显示相同内容,
  但每个选项独占一行. 命令名后的 `!` 与 `showmode!` 的取反是两回事.
- 命令名支持 `se` 和 `set`; 选项名支持 `showmode` / `smd` 和 `tabstop` / `ts`. 输出一律使用完整名称.
- 每条指令只要求处理一个选项或 `all`, 不要求 `:set noshowmode tabstop=8` 这种同时设置多个选项的写法.
  未知选项, 不合法的值或语法使整条指令失败, 不改变任何选项. 这沿用前文的失败规则,
  不要求复现 Vim 某些非法数值被重置的行为.
- 选项改变后立即生效, 但不修改 Buffer 内容, 不影响 modified, register, Repeat 记录或撤销历史.
  打开另一个文件时保留这些设置; 本项目只有一套选项, 不区分全局设置与每个 Buffer 的局部设置.

为了让屏幕评测有确定的答案, 本项目统一采用下面的输出排版, 不要求复现 Vim 的自适应分栏:

- 先显示 `showmode`, 再显示 `tabstop`, 只保留本次需要显示的项. 每项前加两个空格, 例如
  `  showmode  tabstop=4`. 查询结果不使用额外颜色或属性.
- 不带命令名后的 `!` 时, 结果显示在最下面一行, 清除该行旧内容, 正文和正文光标不变.
  没有需要显示的选项时该行为空. 下一次普通按键先清除结果, 再正常处理该按键.
- 带 `!` 时, 每项独占一行, 每行仍以两个空格开头. 若有 N 项, 它们占屏幕底部提示行上方的 N 行;
  最下面一行显示 `Press ENTER or type command to continue`, 光标在提示末尾. 这些临时输出不改变 Buffer 或视口.
  按 `<CR>` 或 `<Esc>` 清除输出, 恢复正文与原光标; 其他按键先恢复屏幕, 再按 Normal 模式处理.
  没有需要显示的选项时不等待按键, 只清空最下面一行.
- 设置, 取反和恢复默认值本身不输出查询结果. 错误提示的具体文字不作要求.

##### 选项变量 (`6pts`)

- 本项目的完整选项列表为 `tabstop` 与 `showmode`; 得分与依赖以目录中的表格为准.

###### `tabstop` (`6pts`)

Tab 的显示宽度由数字选项 `tabstop` 控制. 本项目默认值为 4, 与 Vim 默认的 8 不同, 这是为了与框架保持一致.

- 合法范围为 1 到 9999, 输入为十进制整数. 0, 负数, 超出范围的值和非数字输入均使指令失败, 保留原值.
- Tab 作为一个字符存储, 显示时对齐到下一个制表位, 不转换为空格; `h` / `l` 和 `<BS>` 将一个 Tab 视为一个字符,
  `j` / `k` 按显示列定位.
- 在 Normal 模式下, 光标位于 Tab 展开区域的最后一列; 在 Insert 模式下, 若插入位置在 Tab 前, 光标位于该区域的第一列.
- 插入, 删除, 拆行或合并行后应重新计算 Tab 的显示位置.
- `:se[t] tabstop={value}` 修改宽度后, 所有 Tab 的显示位置与基于显示列的光标定位 (如 `j` / `k`, Tab 展开区域内的光标)
  立即按新宽度重新计算.
- `:se[t] tabstop?` 与 `:se[t] tabstop&` 按数字变量的规则查询 / 恢复默认值.
- 改变宽度后, 保持光标的 Buffer 行号和字符位置, 重新计算屏幕位置, 按需要调整视口, 并更新 `curswant` 为新的显示列.
  Buffer 中的 Tab 字节不变, 不能将它们替换为空格.

###### `showmode` (不单独计分)

这个布尔选项默认打开, 用来检查布尔选项指令的行为, 不额外增加分数.

- 打开时, Insert / Visual / Replace 模式按显示一节的要求显示模式提示.
- 关闭时, 不显示这些提示, 但不会改变当前模式, 输入行为或 Visual 的选区高亮.
- 它不影响命令行输入, 搜索输入框或选项查询结果. 未实现选项功能时, 按默认打开处理, 原有的显示要求不变.

---

#### 显示

##### 模式提示

- `showmode` 打开时 (默认), 在 Insert 模式下, 最下面一行的开头应显示 `-- INSERT --`, 退出该模式后清除.
- `showmode` 打开时, Visual 模式与 Replace 模式同样显示对应提示 (`-- VISUAL --` / `-- REPLACE --`).
  关闭时三个模式都不显示提示; 命令行输入等其他信息不受影响.

##### 命令行显示

- 进入 Command-line 模式时, 保留部分应显示 `:` 与当前输入中的命令.

##### `~` 填充行

- 缓冲区之外的行开头以亮蓝色的 `~` 填充. Advanced 评测固定使用 `xterm-256color` 的色号 12, 默认背景,
  不加粗体等其他属性. 正文中的字面字符 `~` 仍用默认颜色, 真实空行不显示填充符号; Basic 仍沿用默认颜色要求.

##### Visual 选区

- 选中的字符使用反色显示 (ANSI SGR 7), 离开选区或退出 Visual 后恢复原属性. 不要求跟随用户主题改变配色.
- 选中 Tab 时, 它展开后的所有可见列都属于高亮区域. 被选中的换行在该行文字末尾以一个反色空格表示;
  真正空行上的 Visual 光标位置也显示一个反色空格. 选择内容仍按 Visual 一节区分普通空行、末尾空行与空 Buffer,
  不能仅根据屏幕上的反色空格推断是否存在可复制的换行.
- 只高亮屏幕上可见的选区部分, 不高亮缓冲区之外的 `~` 或底部提示行. 端点交换和滚动后应同步更新高亮.

### Vim / vtemu 边界行为复核

2026-09-26 的本地审计通过 vtemu 驱动真实 Vim 9.1, 保存屏幕采样、Buffer、光标与 register 状态.
本节新增的 Replace / Visual 边界例子分别对应审计用例 `replace_cr_bs_restore`,
`replace_delete_then_backspace`, `visual_dollar_then_l`, `visual_r_cursor_newline` 和
`visual_join_one_selected_line`. 这些名称用于标识本地审计记录, 不要求实现同名接口.
若 vtemu 位于同级目录, 可在仓库根目录用以下独立示例复核 `vJ` (无需额外审计脚本):

```sh
printf '%s\n' '<X250>iabc<CR>def<EX>gg0vJ<X150><CURP><P-0;0;2;80><E>' | \
  ../vtemu/bin/vtemu -l 24 -c 80 -- vim -Nu NONE -N -n -i NONE \
  -c 'set noautoindent nojoinspaces ttimeout ttimeoutlen=10 timeoutlen=100'
```

- 这些是 Vim 对照结果, 不表示 MiniVim 实现已经通过测试. 已明确标注的课程差异仍以本 README 为准;
  例如 Replace 输入后又恢复原文本时, modified 仍按 Saved State 的内容比较规则确定, 不能照搬 Vim 的 modified 标志.
- 完整历史审计的 135 个场景中有 16 个 MISMATCH; 其中涉及 `$`, Yank, Visual, Repeat 等的旧预期已经与
  当前 README 不同. 不要把历史报告当作当前规范的失败清单, 也不要仅为消除差异而修改课程规则.
- 复核时固定 Vim 配置与采样时机: Esc 键码等待尚未结束时, 可能采到 Insert 光标而产生多一列的假差异.
  屏幕 `<CURP>` 使用零基坐标, 审计导出的 Buffer 行列使用一基坐标.
- 保存文件的用例应在独立临时目录运行并检查落盘字节; vtemu 退出码或屏幕匹配不能单独证明保存正确.

上述示例应显示 `abc def`, 屏幕光标坐标为 `(0, 3)` (零基). Basic 测试脚本位于 `test/basic/`.

## 调试建议

**(重要) 终端异常时先恢复** 如果进程被强制终止导致 shell 显示异常, 可以在 shell 中运行 `reset` 或 `stty sane`.
正常控制流应依靠 Terminal 的 RAII 自动恢复.

**(重要) VSCode 终端行为**
你大概率需要在 `.vscode` 文件夹的 `settings.json` 里面加上 `"terminal.integrated.allowChords": false`, 从而让 vscode
里面的终端不优先把按键截获并识别为 vscode 的内置快捷键.
